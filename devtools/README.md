# devtools

The Book's tooling. **Nothing here is product**: it is the checks the hooks and the local CI run, the
Book CLI, the guard, and the template `book init` copies. Python 3.11+, standard library only.

| Folder | What it holds | Runs where |
|---|---|---|
| [`checks/`](checks/) | The checks that refuse a bad commit, the generator of `docs/project.md`'s rollups, the local CI run, and their self-tests | `.githooks/pre-commit`, `.githooks/commit-msg`, `ci-local.sh` |
| [`factory/`](factory/) | The Book CLI (`factory.py`, run as `python devtools/book.py <command>`: the `book` command; `factory` before v1.4.0, and no command from v1.5) and the modules it calls for the Git host, the tracker and Drive; `book.py` (init, verify and upgrade); `deploy.py` (used when `[deploy]` is set) | A laptop, or a session |
| [`factory/hooks/`](factory/hooks/) | The guard: refuses in a Claude Code session what `CLAUDE.md` says never to do | **Every Claude Code session in the repository** |
| [`factory/book-template/`](factory/book-template/) | `manifest.toml`, the owner-document `skeletons/`, and the stack and host `packs/` | `book init`, `verify` and `upgrade` |

**Everything project-specific is in [`factory/factory.toml`](factory/factory.toml)**: the names, the
branches, `[guard]`, `[commands]`, `[ai_files]`, the tracker. No tool carries a project's name.

## `checks/` — the checks

| Script | What it does | Runs |
|---|---|---|
| `check-book.py` | The Book's shape: every doc has an owner row (the imported owner tables too), no history inside a current statement, ids defined once, size warnings; the defect ledger's Status words, found dates, and Type and Source (`[book] type_source_from`) | pre-commit, local CI |
| `check-rules.py` | Every *[enforced]* marker names an enforcer that exists, and the table below is current (`--write` rewrites it) | pre-commit, local CI |
| `gen-task-rollup.py` | Writes `docs/project.md`'s *Task progress*, *Open tasks* and *Delivery pace* from each plan's Tasks; `--check` fails when stale | pre-commit, local CI |
| `check-protected-paths.py` | Refuses a change to an existing `requirements/` snapshot or a generated document (`[guard]`) | pre-commit (`--staged`), local CI |
| `check-private-data.py` | Refuses a home path, an email or a secret in written content; `private-data-accepted.txt` lists accepted lines | pre-commit, local CI |
| `check-commit-msg.py` | Imperative subject, no attribution, no trailers; on a `fix/*` branch, a defect or question id (`[checks] fix_id`, plus the `[jira]` key), and every D id it names is in the ledger | commit-msg, local CI |
| `check-code-rules.py` | The lines a commit adds against `[[code_rules]]` (the core's and a stack pack's); the full run also holds each allow-listed file to its count and each `require`d pattern to its minimum | pre-commit (`--staged`), local CI |
| `check-dotnet.py` (dotnet pack) | What needs C#'s shape: a request's list validates its items, options validate on start with a validator behind them, a unique index leads with the tenant key and filters out soft-deleted rows (`[dotnet_checks]`) | pre-commit (a `.cs` file staged), local CI |
| `check-fe-guides.py` (fe-guides pack) | Each route the branch changed in `api-contracts.md` reaches its owner guide, whose *Last checked* line moves (`[fe_guides] owners`) | local CI |
| `check-skills.py` | Every skill loads: frontmatter, name, description length | pre-commit, local CI |
| `task-evidence.py`, `test-trend.py` | A Built task's evidence in git; the self-test counts over time | `/book:progress`, local CI |
| `ledger_ids.py` | Every question's and defect's status, read from their ledgers, and what a line says about one: one reader, not a copy per skill | `/book:sync-sources` (`id_status.py`), `/book:check-guides`, `/book:raise` (`next_id.py`) |
| `run-self-tests.py <folder>` | Runs a folder's `test_*.py` across processes; fails on zero tests or any skip | local CI, `book verify` |
| `ci-local.sh` | The pull request's gate: the checks, the self-tests and `[commands]`, as deep as the change reaches | before a pull request |

**An allow-list lives in `devtools/factory/factory.toml`, never in a check.** Every entry gives its reason,
and one that no longer matches anything fails as stale: `[[code_rules]] allowed` (`{ file, count, reason }`),
`[dotnet_checks]` (`options_unvalidated`, `unique_indexes`, `list_items_nullable`) and `[fe_guides]` (`owners`; `internal_error_codes` for `/book:check-guides`).
A project adds an entry where it keeps a site on purpose; the template ships them empty.

### The local run

`sh devtools/checks/ci-local.sh` reads the base from `factory.toml` (`base_ref`), runs the repository
checks, the self-tests over `[commands] self_tests`, then `[commands] build`, `test` and `integration`
(an empty command is `N/A`, never `PASS`), and prints a *Local CI* section to paste into the pull
request. `book pr open` refuses a commit without its PASS.

## `factory/` — the Book CLI

`python devtools/book.py <command>`:

| Command | What it does |
|---|---|
| `book verify` / `book init` / `book upgrade` | Whether the Book is set up (N1–N22 and the existing checks: READY, READY WITH GAPS, NOT READY); create what is absent from a parameter file; from a newer template, the drift of every template-owned file, with the diffs a person decides on (those `--apply` simply takes go to a file, `--diffs <path>`), and `--apply` to update only the files the project never changed (and remove an unchanged template-copy file the template dropped, RETIRED) |
| `config <key>` / `config --json` | One value, or every value, of the settings — `factory.toml` merged over the Book's defaults — for scripts and skills |
| `book defects classify` | Proposes each open defect's Type and Source from its old Class and Found by; `--apply` writes the columns |
| `impact` / `review-scope` | What a change reaches (modules, tests, docs, risk tier); which review checklist parts it needs |
| `reviewed READY` | Records `/book:self-review`'s verdict for the commit, inside `.git` |
| `pr open` / `pr-check` / `pr whoami` | The Git host (Bitbucket): open a pull request in the person's name, read back its description |
| `ai-files` | A pull request that changes the files that steer the AI was made or approved by an owner |
| `protection --check` | The live branch restrictions against `[protection]` |
| `jira <key>` | One issue, read only |
| `fsd-threads`, `requirements status` | The live specification's comment threads; each source's snapshots |
| `sync-plan` | Brings a plan's Tasks up to date with what has merged |
| `settings --check` | The private settings, by key name: set or not set |

**The settings** are `factory.toml` merged over the Book's defaults by `factory/book_config.py`:
`factory/book-defaults.toml`, then `book-defaults/<stack>.toml`, then each pack's, then the project's file. A
table merges key by key, a list replaces, a list of tables with an `id` (`[[code_rules]]`) merges by id (an
entry left with `enabled = false` is switched off: every reader sees the rule gone), and
`[extend.<table>] key = [...]` appends to the default list. A project's file holds only what is its own. The
pack settings read this way include `[deploy] compose_placeholders`, `[ci_daily] test_database` and
`[database_erd] titles` / `notes`; `[book] skip_skeletons` names a pack's optional document the project does
not keep.

**The lock**, `factory/book-files.lock`, records each Book-owned file's hash as init or upgrade wrote it.
check-book's *Book files* rule (verify N22) fails a commit that changes one, and names where the change belongs
(a setting, the project's `CLAUDE.md`, or `[book] declined`); `[book] drift_accepted = [{ file, reason }]`
makes it a warning. `[book] declined` never names a defaults file or a `.claude/book/` rules file: the
guard's lists and the common rules come from them, so such an entry fails check-book and is not honoured.

Each command that talks to a service holds the credential inside its own process; a session never sees it.
Without a Bitbucket remote the host commands report `N/A`, never `OK`.

## `factory/hooks/` — the guard

`guard.py` is a Claude Code `PreToolUse` hook (`.claude/settings.json`). It reads every file read, file
write and shell command, and refuses what `[guard]` in `factory.toml` says never to do: a change to a
read-only or generated file, a push or commit to a protected branch, a deleted branch, a skipped hook,
a secret or personal path in written content, reading a private settings file or a credential store. It
asks before a write to the files that steer the AI. `guard-config.json` holds its mode (`enforce`).
A refusal that is wrong is a guard bug: report it, never route around it.

## `factory/book-template/` — the template and the packs

| Part | What `book init` does with it |
|---|---|
| `manifest.toml` `[copy] book` | Copies these files from the boilerplate, the source names replaced |
| `manifest.toml` `[skeletons]` | Writes each owner document from its skeleton, `{{name}}`-style values filled, `<!-- FILL -->` slots left for a person |
| `packs/<pack>/` | Copies the pack's files at their target paths when `[book] stack` or `packs` names it |

Packs: `dotnet` (the .NET rules, checks, nested `CLAUDE.md` files and review dimensions), `pytest` (the
Python code rules and test-result check), `deploy` (the DEV/QA deploy skill and its checks),
`bitbucket` (the pipeline and its check), `fe-guides` (the FE guides and their template, their check, and the check, publish and release-notes skills).

## Private settings

**A person's own settings live outside every repository**, in their private settings file —
`~/.boilerplate/local.toml`, or wherever `BOILERPLATE_LOCAL_SETTINGS` points (a Book's own: `~/.<slug>/`
and `<ENV_PREFIX>LOCAL_SETTINGS`). The rule, and why: [the Book's rules](../.claude/book/rules.md#private-settings). A
session never reads it (the guard refuses); the tooling reads only these keys:

| Key | Read by | What |
|---|---|---|
| `[requirements.sources] live_credential` | `book fsd-threads` | How it reaches Google Drive: `"rclone:<remote>"`, or a command that prints an access token |
| `[book] foreign_names` | `book verify` (N20) | Optional: other projects' names, and the words of their domain, that must never appear in this repository, the template included. Private, since the list names them |

`book settings --check` answers by name only — each key `set` or `not set` — and never prints a value.
