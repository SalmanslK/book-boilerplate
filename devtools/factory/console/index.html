Questions & defects

The book's back matter: what the requirements do not answer yet (a person answers these), and what the system does wrong (the factory can fix these).

Requirements

The contract: the client's specification (FSD) in every version the project keeps, and — where an audit has traced it — which requirement is built and proven. What is asked, what is built and what is verified are kept apart.

What the words mean: verified — built, and a test proves it; partly — some of it is built; missing — not built yet; contradicted — built differently from what it says; not checked — the audit could not tell; not ours — out of this project's scope; built, not asked — built, but no requirement asks for it.

Preview a new FSD

Have a newer export of the FSD? Drop the PDF here to see what it changes against the newest copy the project keeps: which numbered sections were added, removed or changed, and which open runs and features each change lands on.

This is a preview only. The PDF is kept by this console, outside the project's folders; nothing in the project changes. Taking it as the project's next copy is a separate step a person decides: Take this as the next version, under the preview, files it and starts a revision run — the AI updates the feature list and the questions, and you approve the result. The project takes at most one copy a week; a second one is the owner's decision.
